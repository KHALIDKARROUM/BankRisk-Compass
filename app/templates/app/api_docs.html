Scoring API

Server-to-server loan-origination-system (LOS) handoff for authenticated, rate-limited, idempotent screening.

Download API reference PDF
API is {% if api_enabled %}configured{% else %}disabled{% endif %}. {% if api_enabled %}Protect the configured key and test against a non-production application first.{% else %}Set a client entry in SCORING_API_KEYS, or the legacy SCORING_API_KEY, to enable scoring.{% endif %}
Documentation format: This page and the PDF are human-readable references, not an interactive API console. Open the machine-readable OpenAPI JSON in an approved viewer or client generator when interactive exploration is required.

Endpoint

POST /api/v1/score/
X-API-Key: <API_KEY>
Idempotency-Key: <UUID>
Content-Type: application/json

Use either X-API-Key or a Bearer token containing the same configured API key. Never put the key in a URL or application log.

Behavior

  • Validates the same contract as the staff form.
  • Stores a durable case and keyed audit fingerprint.
  • Returns the configured client identifier for LOS reconciliation without returning a secret.
  • Replays the same result for a repeated idempotency key and identical payload.
  • Rejects the same key with a different payload instead of silently overwriting a case.
  • Does not generate explanations or adverse-action reasons.

Example request

curl --request POST http://127.0.0.1:8000/api/v1/score/ \
  --header "X-API-Key: <API_KEY>" \
  --header "Idempotency-Key: 4f5fb57a-f5af-4ff1-b4aa-56b8bb4fe012" \
  --header "Content-Type: application/json" \
  --data @application.json

LOS integration: store the returned case_id and the original idempotency key in the loan-origination system. Retry a timeout only with the identical request and same key. See the integration guide for reconciliation, credential rotation, and pilot acceptance checks.

Response and error contract

HTTP responses returned by the scoring API
StatusMeaningCaller action
200Score returned or idempotent replayStore the case ID and continue the staff workflow.
400Malformed JSON, invalid idempotency key, or field validation failureCorrect the request; inspect the returned fields object when present.
401Missing or invalid API keyCheck secret injection without logging the key.
409Idempotency key was already used with different inputDo not retry under that key; investigate the caller’s request identity.
422Valid input is materially outside the supported model domain; no score was producedVerify the input and route the application to the approved non-model process.
429Per-minute rate limit exceededWait for the Retry-After interval before retrying.
503API disabled or approved model unavailableStop scoring and escalate to the service owner.

Reuse an idempotency key only when retrying the same logical request. Keep the original payload with the case ID in the calling system’s audit record.
